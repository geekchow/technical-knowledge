KV Cache 完整通俗讲解
一、全称
Key-Value Cache，键值缓存，是大模型（Transformer）推理加速最核心技术。
二、底层原理背景
大模型是 Transformer 架构，生成文字是逐字预测：
输入一句话 → 输出第 1 个字；
把原文 + 刚输出的第 1 字再喂进去 → 输出第 2 个字；
循环直到结束。
每一轮计算都会执行自注意力 Attention：
对所有历史 token 生成 Query (Q)、Key (K)、Value (V)
Q 和所有 K 做点积打分，再乘 V 得到输出
问题：每生成一个新字，都要重新计算全部历史 token 的 K、V，重复计算，速度极慢、显存占用爆炸。
三、KV Cache 解决了什么
只计算新 token 的 K、V，历史所有 token 的 K、V 直接存起来复用，不用重复算。
第一轮：输入我爱，算出 Kv₁、Kv₂，存入显存缓存
生成第一个字吃：只算吃的 Kv₃，拼接缓存里的 Kv₁、Kv₂做注意力
生成第二个字饭：只算饭的 Kv₄，直接拼接旧缓存
全程历史 KV 不再重复计算，大幅减少算力消耗。
Key / Value 各自作用
Key(K)：记录每个历史 token 的特征，用来和新 Query 匹配相似度
Value(V)：存储 token 原始信息，相似度加权后用来生成下一词
缓存就是把所有历史 token 的 K、V 张量持久保存在 GPU 显存。
四、核心优缺点
优点
推理速度提升几倍到十几倍，是线上服务必备优化
降低重复矩阵运算，减少 GPU 算力浪费
缺点
显存占用随生成长度线性暴涨
生成越长的文本（万字长文、超长对话），缓存 KV 矩阵越大，很容易爆显存 OOM。
上下文越长，读写 KV 缓存的带宽开销上升，速度会逐渐变慢
五、常见配套优化技术（和 KV Cache 绑定）
PagedAttention（分页 KV 缓存）
主流框架 vLLM、SGLang 核心优化，把 KV 缓存像操作系统内存分页管理，减少显存碎片，大幅提升并发量。
KV Cache 量化（INT4/INT8 KV）
KV 张量用低精度存储，显存占用减半 / 减至 1/4，轻微损失精度。
滑动窗口 KV Cache
超长对话只保留最近 N 个 token 的 KV，丢弃久远历史，控制显存上限（适合长文本问答）
投机解码 (Speculative Decoding)
配合 KV 缓存进一步降低单步推理耗时
六、举个直观例子
提示词：写一句夏天的短句
初始输入 6 个 token，一次性算出 6 组 KV 存入缓存
模型输出风：仅计算风的 KV，拼接旧 6 组 KV 计算注意力
模型输出吹：仅计算吹的 KV，复用前面 7 组缓存
没有 KV Cache 的话，每输出一个字，都要重新计算前面全部 token 的 KV，越往后越卡。
七、应用场景
所有大模型线上推理：聊天机器人、AI 绘画文字生成、代码补全、本地部署 LLM，只要是自回归生成任务，全部依赖 KV Cache 提速。

# 逐句拆解：对所有历史token生成 Q / K / V（Transformer自注意力底层逻辑）
## 前置基础
1. Token：文本切分后的最小单元（汉字/单词/标点），一段对话所有输入+已经生成的文字统称**历史token**。
2. Transformer 自注意力核心逻辑：
模型要判断「当前新词」和「上下文每一个历史词」的关联强弱，关联越高，这个历史词对当前词的生成影响越大。
3. 三个向量分工：
- Q = Query 查询向量：代表**当前正在计算的token**，我是谁、我要找什么样的上下文；
- K = Key 键向量：代表**每一个历史token**的特征标签；
- V = Value 值向量：代表**每一个历史token**携带的实际内容信息。

## 一、怎么生成 Q、K、V 向量？
每一个token都会先转换成固定维度的**词嵌入向量embedding**（数字数组，代表文字语义）。
模型内置3组独立可训练权重矩阵：$W_Q、W_K、W_V$
计算统一公式：
$$
Q = X W_Q,\quad K = X W_K,\quad V = X W_V
$$
$X$ = 所有历史token的嵌入向量矩阵（整段上下文打包在一起）
流程：
1. 把全部历史token拼成矩阵X；
2. X分别和三个权重矩阵做矩阵乘法；
3. 一次性输出整套Q矩阵、整套K矩阵、整套V矩阵，**每个token对应一组(Q,K,V)向量**。

## 二、分开理解三者作用（重点）
### 1. Query (Q)：查询者，只有当前token才有有效Q
自回归生成场景（聊天、续写）里：
我们**只需要下一个新词**，每次只有**最新1个token**作为查询主体，它的Q用来去匹配全文所有历史token。
旧历史token的Q在推理时完全不会再使用，这也是KV Cache只存K、V，不存Q的根本原因。

### 2. Key (K)：每个历史token的“索引标签”
所有历史token都会生成专属K向量，相当于每个词的检索标签。
匹配逻辑：用当前token的Q，和**每一个历史token的K做内积**，内积数值越大 → 两个词语义越相关。
例：上下文是「猫咪在窗边睡觉」，当前Q是“它”，和“猫咪”的K点积分数最高，模型就知道“它”指代猫。

### 3. Value (V)：每个历史token的“真实内容”
K只负责打分匹配，真正用来计算输出语义的是V。
步骤：
1. Q与全部K计算相似度分数；
2. 分数做softmax归一化，得到权重；
3. 用权重加权求和全部历史token的V向量，得到当前token最终输出特征。

简单类比数据库检索：
- Q = 你的搜索关键词
- K = 数据库里每条数据的标题/索引
- V = 数据库每条数据完整正文
先拿关键词匹配索引打分，再按分数调取对应正文合并得到结果。

## 三、“对所有历史token生成QKV”完整运行流程举例
上下文（全部历史token）：`[我, 今天, 吃, 了, 草莓]`
1. 5个历史token转为嵌入矩阵X；
2. X × WQ → 5行Q向量，每行对应一个词的Query；
3. X × WK → 5行K向量；
4. X × WV → 5行V向量；
5. 取最后一个token「草莓」的Q，分别和5个K计算相似度；
6. 根据相似度权重融合全部5个V，算出下一个字（比如：很甜）。

## 四、为什么没有KV Cache时，每一步都要重复生成全部历史token的K、V？
当模型输出新字「很甜」，此时完整历史变为：`[我,今天,吃,了,草莓,很,甜]`
若无缓存：
每生成一个新词，都会把**全部上下文**重新过一遍 $W_K、W_V$，从头到尾重新计算所有旧token的K、V，大量重复运算，显存、算力双重浪费。
有KV Cache：
第一次算出的5组K、V永久保存在显存，新增的「很、甜」只单独计算自身K、V，拼接原有缓存即可，旧token不再重复计算。

## 五、补充多头注意力补充说明
实际大模型是多头注意力，会拆分多组独立$W_Q/W_K/W_V$，每组各自生成一套QKV、单独计算匹配，最后拼接融合。逻辑完全不变，只是多并行多组检索，捕捉更细粒度语义关联。
