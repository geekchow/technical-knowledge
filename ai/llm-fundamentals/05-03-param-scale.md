# 深潜 3 · 参数规模：为什么 7B、70B、670B 如此重要

> **你在哪里**：第三个深潜，权重栈的专题——聚焦"大小"。角色回顾：Transformer 权重栈**唯一职责是存储全部语言能力与知识**。它对应运行示例的**第 4 步**：代码两边都对，解释质量却分出高下。

## 参数到底是什么

参数（权重）就是模型里那些可训练的浮点数——注意力矩阵 $W_Q/W_K/W_V$、MLP 层、词嵌入表里的每一个数。"8B"= 80 亿个这样的数。训练是调这些数，推理是读这些数，**模型文件的全部内容就是这堆数**。

参数量直接决定三件事：**装多少知识、要多少显存、每个 token 花多少钱**。逐个看。

## 一、能力维度：Scaling Law——"更大就是更好"的定量版

2020 年 Kaplan 等人的发现改变了行业：**模型损失（loss）随参数量、数据量、算力按幂律平滑下降**，跨越好几个数量级都成立。这意味着能力提升**可预测**——投入 10 倍算力，就能提前算出 loss 降到哪。"大力出奇迹"从玄学变成了工程学，这就是行业敢押注千亿美元建集群的数学依据。

两个修正让图景完整：

- **Chinchilla（2022）**：给定算力，参数和数据要**配比**——最优比例约每参数 20 个 token。之前的大模型普遍"参数过大、数据不足"，白白浪费算力；
- **后 Chinchilla 时代的反转**：Chinchilla 只优化训练成本，但**推理要跑无限次**。于是行业转向"小模型 + 超量数据"：Llama-3-8B 被喂了 15T token（每参数约 1900 个 token，是 Chinchilla 最优的 90 倍）——训练时多花钱，换一个部署便宜、跑得快的小模型。**今天的 8B 远强于三年前的 8B，原因就在这里。**

能力还有**涌现**的一面：某些能力（多步推理、遵循复杂指令、上下文学习）在小模型上近乎为零，跨过某个规模后快速出现。这解释了示例第 4 步——"写对代码"是 8B 就充分掌握的模式，"把平方根原理讲透、自发处理 0/1/负数"需要更深的推理链条，规模差距在这里显形。

## 二、物理维度：参数量 = 显存账单

$$
\text{权重显存} \approx \text{参数量} \times \text{每参数字节数}
$$

| 模型 | FP16 | INT4 量化 | 意味着 |
|---|---|---|---|
| 8B | 16 GB | ~4.5 GB | 量化后笔记本/手机可跑 |
| 70B | 140 GB | ~40 GB | FP16 要 2×A100；量化后单卡勉强 |
| 670B (DeepSeek-V3 满血) | ~1.3 TB | ~350 GB | 多机集群起步 |

这就是"为什么参数规模 cares"最硬的一半：**它划定了谁能把模型跑起来**。8B 是"个人设备级"，70B 是"单机多卡级"，数百 B 是"集群级"——参数量直接决定开源模型的可及性阶梯。

推理速度同理（见[深潜 2](05-02-inference-engine.md)）：decode 每 token 读一遍全部权重，**参数量翻倍 ≈ 单 token 搬运成本翻倍** ≈ API 定价翻倍的物理基础。

## 三、打破"参数量=能力"简单等式的三股力量

1. **MoE（混合专家）**：DeepSeek-V3 总参数 671B，但每个 token 只激活 37B——**知识容量按总参数算，单 token 成本按激活参数算**，一个数字拆成了两个。看模型规格表时这两个数都要看；
2. **蒸馏（distillation）**：让小模型学大模型的输出，把能力"压"下来——今天的强 8B 多半有大模型老师；
3. **测试时计算（test-time compute）**：推理模型（o1/R1 式）用更长的思考链换更强的推理——**在推理侧花 token，部分替代在参数侧花容量**。这是"参数规模不再是唯一杠杆"的最新变量。

三股力量共同解释了一个趋势：**能力前沿仍靠大参数推进，但"单位能力的参数量"在持续下降。**

## ⚓ 回到示例

运行示例第 4 步展开——三个数字全部落地：

- **16 GB**：8B × 2 字节（FP16），你硬盘上那个权重文件的大小由参数量直接决定；能装进 MacBook，正是你能本地跑它的全部原因；
- **代码都对**：质数判断在语料中是高频模式，8B 的容量+15T token 的超量训练足以牢固掌握——后 Chinchilla 策略的直接受益；
- **解释分高下**：严谨的数学表述、自发覆盖边界情况，属于随规模增强的深层能力——Claude 的参数规模（加上更重的后训练）让它在"知识之上的推理与组织"上拉开差距。同时你也为此付费：更大参数 = 每 token 更高的搬运成本 = API 账单。

## 失败行为

- **装不下**：显存不足直接 OOM——参数规模的硬失败；量化是主要逃生通道（INT4 精度损失通常可接受）；
- **容量不足的软失败**：小模型在长尾知识上压缩失真更严重 → 幻觉率更高、复杂指令跟丢——不报错，只是悄悄变差，比 OOM 更危险；
- **跑分幻觉**：小模型可以在针对性刷分后单项超越大模型，但泛化面（没刷过的任务）差距仍在——选型时警惕单一 benchmark。
