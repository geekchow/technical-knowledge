# 04 · 运行示例：一个问题、两个模型

> **你在哪里**：这里定义贯穿全篇的主线场景。之后每个深潜都会回到它，最后的 walkthrough 会带着全部深度重跑它。

## 场景（三句话）

你在笔记本上用 ollama 跑着**开源的 Llama-3-8B**，同时开着**闭源的 Claude API**。你把同一个问题发给两边：

> "写一个 Python 函数判断质数，并解释为什么只需要检查到平方根。"

两边都给出了正确代码，但 Claude 的解释明显更严谨、边界情况（0、1、负数）处理更周全——**为什么？答案要动用地图上的每一个概念。**

## 浅层追踪：每一步谁在场上

**第 0 步 · 能力从哪来（早已发生）**
两个模型的能力都来自各自的**训练管线**：数月前，万亿级 token 语料被**预训练**压缩进**参数**，再经 **SFT + RLHF 后训练**变成听话的助手，产出一份静态**权重文件**。你提问时，训练早已结束退场。

**第 1 步 · 两条路，同一份原理**
- 本地这路（**开源**）：Llama-3-8B 的权重文件（约 16 GB，FP16）躺在你的硬盘上，**ollama**（推理引擎）把它加载进你笔记本的显存/内存；
- 云端这路（**闭源**）：Claude 的权重你永远看不到，请求通过 **API** 进入厂商的推理集群——那边跑的推理引擎原理与你本地的一模一样，只是规模大得多。

**第 2 步 · Tokenizer 上场**
两边各自的 **Tokenizer** 把你的问题切成 token ID 序列（各家词表不同，切法不同，token 数也略有差异）。

**第 3 步 · 推理引擎读权重**
**Prefill** 并行吃下全部输入 token，写出 KV Cache；**decode** 开始逐 token 生成——每个 token 都要把全部权重读一遍。8B 模型在你笔记本上约十几 token/s；Claude 那边虽是更大的模型，靠数据中心 GPU 和批处理照样流畅。

**第 4 步 · 参数规模显形**
代码两边都对——判断质数在预训练语料里出现过成千上万次，8B 的容量足够。但"为什么只需检查到平方根"的**解释质量**分出了高下：更大的**参数规模**意味着更大的知识容量和更强的推理链条（**Scaling Law** 在起作用），frontier 模型的后训练投入也远更充分。

**第 5 步 · 回答返回，痕迹不同**
你本地的对话没有离开过你的电脑（**开源**部署的隐私属性）；API 那路按输入/输出 **token 计费**，账单和数据治理条款是**闭源**交付形态的一部分。

## 这个示例触到了地图上的一切

| 概念/角色 | 在示例中的落点 |
|---|---|
| Token / Tokenizer | 第 2 步，两家词表切分同一问题 |
| 参数/权重栈 | 16 GB 的 Llama 权重文件 vs 看不见的 Claude 权重 |
| 预训练 / 后训练 | 第 0 步，能力的来源；解释质量差距的一半原因 |
| 推理引擎 | 第 1、3 步，ollama 和厂商集群跑同一套 prefill+decode |
| Scaling Law / 参数规模 | 第 4 步，8B 与 frontier 的能力差、以及 16 GB 这个数字本身 |
| 开源 vs 闭源 | 第 1、5 步，下载权重 vs 调 API，隐私 vs 账单 |

## 质量自检

不看上文，你应该能复述：问题被 tokenizer 切分 → 本地 ollama / 云端集群各自加载权重做 prefill+decode → 两边都给出代码 → 解释质量差距来自参数规模与训练投入 → 本地路隐私自持、API 路按 token 计费。每一步你知道**谁在场上**，但还不知道任何角色的**内部构造**——四个深潜，逐个拆开。
