# 完整重演：带着全部深度重跑运行示例

> 十二篇文章，每一篇都在往同一张地图的某一格里填内容。这一篇把它们缝成一个连续的故事。
>
> 同一个问题、两个模型——但这次每一跳都能看到内部：从六个月前那个跑着 1.6 万张 H100 的集群，到你按下回车后的第 50 毫秒，再到最后那两张形态完全不同的收据。
>
> 然后是七个动手练习。**每个练习验证一篇文章的一个具体论断**——不是"跑一下试试"，而是"亲眼看到这个数字对不对"。纸面理解和手感之间的距离，只能靠这些练习跨过去。

---

## 场景重申

笔记本上用 ollama 跑着 **Llama-3-8B-Instruct**（开源），旁边开着 **Claude API**（闭源）。同一个问题发给两边：

> **"写一个 Python 函数判断质数，并解释为什么只需要检查到平方根。"**

## 全深度时间线

### T−6 个月 · 训练侧

**Meta 的集群上**（[06 · 训练管线](06-training-pipeline.zh.md)）：

约 15T token 的清洗后语料——经过去重、质量分类器过滤、代码与多语言配比调优——以"预测下一个 token"为目标，反复冲刷 80 亿个随机初始化的浮点数。1.6 万张 H100 连续运转数月，MFU 大约在 40% 上下，另一半算力被通信和同步吃掉。

GitHub 上无数份 `is_prime` 实现、数学教材里"若 $n = a\times b$ 且 $a \le b$ 则 $a \le \sqrt{n}$"的论证，都在交叉熵损失的驱动下被压进权重——**具体压进了哪里？** 主要是每层 FFN 那 1.76 亿个参数里（[04 · Transformer 内部构造](04-transformer.zh.md)：FFN 占全部参数的约 70%，是知识仓库）。

期间 loss 曲线大概率炸过至少一次，工程师回滚 checkpoint、跳过坏批次、重来。

预训练产出一个**只会续写的基座模型**。此时你问它"法国的首都是哪？"，它会续写"B. 里昂 C. 马赛……"。

接着（[07 · 后训练细拆](07-post-training.zh.md)）：**SFT** 用几十万条"指令 → 理想回答"教会它问答格式，loss 只在助手回复的 token 上计算；**拒绝采样**用奖励模型从多个生成里挑最好的回炉；**DPO** 用偏好对把"简洁正确"的风格压进权重。

最终 16 GB 的 safetensors 文件被放上公网——**开源分叉发生**（[12 · 开源 vs 闭源](12-open-vs-closed.zh.md)）。

**同期，Anthropic 的管线**做着结构相同的三级流水，但参数规模更大、数据配比更精细、后训练重得多：重型 RLHF、Constitutional AI 的自我批评修订、RLAIF、以及可验证奖励上的推理强化。权重留在了自家集群——**闭源分叉**。

> **这一步决定了后面的一切。** 你稍后看到的能力差距，在这一刻就已经完全确定了。

### T−0 · 加载

你敲下 `ollama run llama3`。16 GB 权重被载入 MacBook 的统一内存——**这个数字来自 8B × 2 字节（FP16）**，[09 · 参数规模](09-param-scale.zh.md) 的公式，一个字都不用改。

如果这是 70B，数字会是 140 GB，故事在这里就结束了。**参数量划定了谁能把模型跑起来。**

同一时刻，Claude 的权重常驻在数据中心的几百张 GPU 上，被数万用户通过连续批处理分时共享。

### T+0ms · 你按下回车

两边各自的 **Tokenizer** 把问题切成 token ID（[05 · Tokenizer](05-tokenizer.zh.md)）。

Llama-3 的 128K 词表下大约 30 个 token；Claude 的词表和合并规则完全不同，**切出的 token 数和边界都不一样**。两边的账单基准从第一步起就分岔了。

注意这一步之后，"文字"彻底消失了。剩下的全程都是向量运算，直到最后一步才变回 token。

### T+50ms · Prefill

30 个 token 一次并行前向（[08 · 推理引擎](08-inference-engine.zh.md)）：

每个 token 先查嵌入表变成 4096 维向量，然后进入 32 层的循环。处理"质数"这个 token 时，它的 Q 与"判断"、"函数"、"Python"的 K 强匹配——**上下文告诉模型这是编程任务而非数学科普**，输出的整体形态在这一步就定了调。同时 FFN 里那些被"质数"激活的神经元，把权重里存的 `is_prime` 模式调了出来。

每层的 K/V 写入 **KV Cache**（8B 模型每 token 128 KB × 32 层 → 30 个 token 约 3.8 MB，微不足道）。最后一个位置的概率分布中采样出第一个输出 token——大概率是 `def`，因为在这个上下文下它的 logit 远高于其他 12.8 万个候选。

30 个 token 的 prefill 几乎瞬间完成。**你感受到的首字延迟，主要来自模型加载和网络往返，而不是计算**——如果你粘的是一篇 5 万字的文档，故事会完全不同（[10 · 上下文窗口](10-context-window.zh.md)：prefill 的注意力计算量随长度平方增长）。

### T+100ms ~ T+30s · Decode 循环

两边同时进入逐 token 生成。每一步：读全部权重 + 全部 KV Cache → 前向 → 采样 → 新 token 的 K/V 追加进缓存。

**本地 8B**：权重 16 GB，MacBook 统一内存带宽约 400 GB/s → 理论上限约 25 token/s，实测十几 token/s。

这个数字**完全由带宽决定，和你的 CPU 多快、GPU 算力多强都没关系**（[08 · 推理引擎](08-inference-engine.zh.md)）。此刻你笔记本的算力利用率大约在 1% 上下——99% 的时间在等数据从内存搬过来。

**Claude 那边**：模型大得多，单 token 搬运成本更高。但数据中心的 HBM 带宽是消费级硬件的数倍，加上连续批处理把权重搬运成本摊给了同批次的几十个请求——**你感受到的速度不落下风**。

你看到两个打字机同时打字。**两边跑的是同一套物理，差别只在规模和工程。**

### 输出对比 · 参数规模显形

**两边的代码都对**：

```python
def is_prime(n: int) -> bool:
    if n < 2:
        return False
    for i in range(2, int(n**0.5) + 1):
        if n % i == 0:
            return False
    return True
```

质数判断是预训练语料里的超高频模式，8B 的容量加上 15T token 的超量训练（后 Chinchilla 策略，[09 · 参数规模](09-param-scale.zh.md)）足以牢固掌握。**这类任务上，参数规模的边际收益已经趋近于零——花十倍的钱买不到更对的 `is_prime`。**

顺带一提，这里也**没有发生幻觉**（[11 · 幻觉的机制](11-hallucination.zh.md)）：高频知识压缩得极好、失真极小。日常使用中"模型很靠谱"的印象，很大程度上来自我们问的大多是这类问题。

**解释分出高下**：

- **8B**：正确但单薄的一句"因为因子成对出现"；
- **Claude**：完整论证——若 $n = a \times b$ 且 $a \le b$，则必有 $a \le \sqrt{n}$，故 $\sqrt{n}$ 以内无因子即可断定为质数——并自发说明 0、1、负数按定义不是质数、代码为何用 `n < 2` 一并处理。

这个差距可以精确拆成两半：

| 来源 | 机制 |
|---|---|
| **参数规模**（[09](09-param-scale.zh.md)） | 更多层 = 更多次信息加工 = 更长的推理链可以走完；更大的 FFN = 更丰富的记忆可调用 |
| **后训练深度**（[07](07-post-training.zh.md)） | "周全性"在偏好训练里被系统性奖励；数学严谨性带着 RLVR 一代推理训练的印记 |

**同一份预训练知识，取出来的成色由后训练配方决定；能取出多深，由参数规模决定。**

### T+30s · 落幕，两张不同的收据

**本地这路**（[12 · 开源 vs 闭源](12-open-vs-closed.zh.md)）：
对话从未离开你的机器，KV Cache 随 ollama 会话释放。成本：几分钱电费。你还保有全部后续权利——明天可以 LoRA 微调它，让它记住你公司的术语。

**云端这路**：
厂商推理集群释放你的批次槽位，计费系统按输入约 30 + 输出约 400 token 记账。输入走 prefill（并行、便宜），输出走 decode（逐个、带宽受限、贵）——**这就是几乎所有厂商输出定价都是输入 3~5 倍的物理原因**。

你买到了前沿质量，交出了数据经手权和每 token 的钱。

## 收束：回到第 1 篇的问题

[01 · 为什么会有 LLM](01-why.zh.md) 里的三个痛点是：**碎片化、标注昂贵、零泛化**。

刚才这 30 秒里：

- **没有任何人为"质数解释"这个任务标注过一条数据、训练过一个专用模型**——标注成本痛点，消失；
- **一个通用模型靠一句自然语言完成了代码生成 + 数学论证的复合任务**——碎片化痛点，消失；
- **两个不同厂商、不同规模、不同交付形态的模型都能做到**，而且这个任务从来不在任何训练目标里——零泛化痛点，消失。

用旧范式做同样的事，你需要一个代码生成模型、一个数学解释模型、以及把两者串起来的胶水逻辑，周期以季度计。

**Stage 1 的三个痛点，在这个日常到不起眼的场景里被全部解决——这就是 LLM 存在的理由。**

## 动手练习：七个验证

每个练习验证一篇文章的一个具体论断。建议按顺序做，每个 10~30 分钟。

### 练习 1 · 亲眼看到基座模型"只会续写"

**验证**：[06 · 训练管线](06-training-pipeline.zh.md) —— 预训练产出的是续写器，SFT 才教会它回答。

```bash
ollama run llama3.2:1b        # Instruct 版本
> 法国的首都是哪？
# → "巴黎。"
```

然后找一个**不带 `Instruct`/`Chat` 后缀**的 base 模型（HuggingFace 上搜 `-base` 或 `text` 版本）问同样的问题，观察它续写而不回答的行为。

**这是全部练习里最能带来"啊哈"感的一个**——SFT 的价值会在这一刻变得极其具体。

### 练习 2 · 数一数 token，感受中文税

**验证**：[05 · Tokenizer](05-tokenizer.zh.md) —— 同一句话在不同模型下 token 数不同，中文更贵。

```python
from transformers import AutoTokenizer

texts = ["Hello, how are you today?", "你好，今天过得怎么样？"]
for name in ["meta-llama/Llama-2-7b-hf", "meta-llama/Meta-Llama-3-8B"]:
    tok = AutoTokenizer.from_pretrained(name)
    for t in texts:
        print(name, repr(t), len(tok.encode(t)))
```

顺便试试 `tok.tokenize("strawberry")`，亲眼看到字母 `r` 是如何在模型看到之前就消失的。

### 练习 3 · 用体积和速度反推参数量

**验证**：[09 · 参数规模](09-param-scale.zh.md) —— 显存 = 参数量 × 每参数字节数；decode 速度由带宽决定。

```bash
ollama list                      # 看每个模型的文件体积
ollama run llama3.2:1b --verbose # 记录 eval rate (token/s)
ollama run llama3.1:8b --verbose
```

用文件体积除以参数量，验证"每参数几字节"；再对比两个模型的 token/s，**看看比值是否接近它们体积的反比**——如果接近，你就亲手验证了"decode 是带宽受限"这个结论。

### 练习 4 · 量化：精度换显存和速度

**验证**：[09 · 参数规模](09-param-scale.zh.md) 与 [FP16 与 INT4 量化](../llm-inference/fp16-int4-quantization.zh.md)。

拉取同一模型的 `q4` 和 `q8` 版本，对比三件事：文件体积、生成速度、回答质量。

**重点关注速度**：很多人只知道量化省显存，但因为搬运的数据变少了，**它同时直接提速**。

### 练习 5 · 看到能力阶梯

**验证**：[09 · 参数规模](09-param-scale.zh.md) —— 涌现与深层能力随规模增强。

同一个复合问题（"写代码 + 解释原理"类）分别问 1B、8B、以及一个 API 上的前沿模型。

**不要看代码对不对**（都会对），**看解释的深度**：有没有完整论证、有没有主动覆盖边界情况、有没有提到反例。这就是示例第 4 步的差距，在你自己手上重现。

### 练习 6 · 触发一次幻觉，再治好它

**验证**：[11 · 幻觉的机制](11-hallucination.zh.md)。

三步：

1. 问一个**长尾 + 需要精确细节**的问题（某个小众库某个版本的某个参数），观察模型给出格式完美的答案；
2. 去官方文档核对——大概率对不上；
3. 现在做两个对照实验：**(a)** 在提示词里加"如果不确定，请直接说明，这是被鼓励的行为"；**(b)** 把真实文档粘进上下文再问一遍。

对比三次的结果。**你会直观地理解为什么 RAG 是唯一改变问题性质的手段，而"请不要编造"效果有限。**

进阶：同一个问题采样 5 次，看编造的内容是否每次都不一样——这就是自洽性检查的原理。

### 练习 7 · 亲手体验开源的定制权

**验证**：[12 · 开源 vs 闭源](12-open-vs-closed.zh.md) 与 [07 · 后训练细拆](07-post-training.zh.md)。

在 HuggingFace 上找一个 LoRA 微调教程，用 100 条自己领域的数据微调一个 1B~8B 的小模型。

两个观察点：

- **它确实学会了你的格式和语气**——这是微调擅长的；
- **它并没有真的记住你的知识**——随便问一个数据里没有的相关问题，它会编。**这就是"微调教格式、RAG 注知识"这条经验的第一手证据。**

如果你还想更深一步：跑一遍通用能力的回归测试，看看灾难性遗忘有没有发生。

## 一页带走全部

| 问题 | 一句话答案 |
|---|---|
| **训练 vs 推理？** | 写入 vs 读取。训练把数据压进权重（一次、极贵、跑完退场），推理只读权重生成回答（无限次、逐 token、绝不修改） |
| **模型内部长什么样？** | 嵌入表 → 32 层（注意力横向通信 + FFN 纵向计算）→ 输出头。**70% 的参数在 FFN**，那才是知识仓库 |
| **为什么模型数不清字母？** | Tokenizer 在训练前就把文本切成了 token，字母从没单独出现过。**词表冻结，此缺陷无法靠训练修复** |
| **99% 的算力花在哪？** | 预训练。后训练不到 1%，但它决定了模型能不能用——**预训练定能力上限，后训练定可用性** |
| **为什么第一个字慢、后面匀速？** | Prefill 并行吃输入（算力受限），Decode 逐 token 生成（**内存带宽受限**，算力利用率不到 1%） |
| **参数规模为什么重要？** | 一个数字三重命运：能力上限（Scaling Law）、显存门槛（参数 × 字节数）、单 token 成本（decode 读全部权重） |
| **128K 上下文能装满吗？** | 三个上限：架构上限（规格表）、显存上限（KV Cache）、**有效上限（通常只有标称的 1/3~1/2）**。中段最容易被忽略 |
| **幻觉能修好吗？** | 不能。有损压缩 + "合理而非真实"的目标函数 + 训练全程奖励自信 = 固有属性。**只能压低并检测，按"它一定会错"设计系统** |
| **开源 vs 闭源？** | 同一份权重的两种交付：公开下载（控制权、隐私、可复现）vs API 出租（前沿能力、零运维）。**技术栈相同，合约不同** |
| **该怎么选？** | 三个问题：数据能出域吗 → 能力够吗 → 用量摊得平吗。真实生产系统里往往不是二选一，是一张路由表 |
